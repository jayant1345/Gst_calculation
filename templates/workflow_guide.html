What this page is

A step-by-step walkthrough of how bank statements turn into the CA's GST working sheet in this app - so you (or the CA) can follow it without asking anyone. This mirrors the CA's own written workflow specification (NUTAN INCOME WORKFLOW) exactly.

1

Upload branch statements Income & Output GST

Drag and drop PDF/Excel branch statements (or a whole folder). Nothing changes here from how you've always done it - the app reads each account's income as credit total minus debit total for the period, rounds to 2 decimals, and auto-computes CGST/SGST at 9% each.

2

Check the "Needs Review" banner Income & Output GST

After upload, a yellow banner appears if anything needs a second look - a GL/PL code the app has never seen before, a manual-entry code (see step 3), or a locker/guarantee code with signs of an internal transfer. Click "Show these entries" to jump straight to them.

3

Classify GL/PL codes (once per code) Manage GL/PL Codes

This is the one-time setup step. Open Manage GL/PL Codes (button above the branch table) and tell the app how to treat specific codes - see the reference table below for exactly which ones. Type a code or particulars into the search box to find it fast; the field also suggests matches as you type.

  • New/unrecognized codes default to 18% Taxable until classified - never silently exempt.
  • Editing a code here retroactively fixes every already-uploaded entry using it.
4

Fix manual-entry and ledger-balance figures Income table / Ledger section

Codes marked Manual (like PL 3230, PL 3320) show a pencil icon next to their amount in the main table - click it to type the correct figure. GL 1878/1879/1880 and exempt-income codes appear lower on the page under "GST Payable Ledger & Exempt Income", each with its own pencil icon if the closing balance needs correcting.

5

Export the CA Working Sheet Income & Output GST

Click Export CA Working Sheet. Every branch tab, Sheet1, and SUMMARY SHEET GST are filled from real uploaded data, plus two new tabs:

  • GST Payable Reconciliation - each branch's computed CGST/SGST/IGST vs. the bank's own ledger figure, with the difference. Any branch tab where the difference exceeds ₹10 turns red automatically.
  • Exempt Income Working Sheet - this month vs. last month's closing balance for each classified exempt-income code, and the difference.

Quick reference - what to set for which codes

Code(s)What it isSet in Manage GL/PL Codes
PL 3230, PL 3320 Guarantee commission / locker rent - prone to internal accrual transfers that confuse auto-reading. Entry Method: Manual
Any DEMAT-branch code paid on inter-state exchange dealings Some DEMAT income is IGST instead of CGST+SGST. Only applies inside the DEMAT branch, never elsewhere. Tax Type: IGST @ 18%
GL 1878, 1879, 1880 The bank's own GST-payable ledger accounts - one each for CGST, SGST, IGST. Only your chart of accounts says which is which. Ledger Role: GST Payable (CGST / SGST / IGST)
~14 named codes (dividend, interest exempted, provisions written back, income tax refund, etc.) The CA's exempt-income list for the separate working sheet. Ledger Role: Exempt Income Item

Common questions

Why does a code default to 18% Taxable instead of asking me first?

Because guessing "exempt" on income that's actually taxable is the dangerous direction to be wrong in for GST. The app defaults to the safe-but-flagged option and waits for you to confirm via Manage GL/PL Codes - it never silently exempts something.

A branch tab turned red in the export. What does that mean?

The GST the app computed from that branch's income differs from what the bank's own GL 1878/1879/1880 ledger says by more than ₹10. Check the GST Payable Reconciliation sheet for the exact numbers, then verify against the branch's original statement.

The Exempt Income sheet shows "—" for last month. Is that a bug?

No - it means there's no captured closing balance for the previous period yet (either it's the first month this code has been tracked, or the statement for that period wasn't uploaded). It will fill in automatically from the next month onward.

I deleted a code by mistake, or classified something wrong. What happens to already-uploaded data?

Nothing is deleted from your records. Editing or deleting a code re-flags every entry using it as "Needs Review" (or recomputes it, if you're correcting rather than removing) so you can catch and fix it before filing - it never silently changes numbers you can't see.
