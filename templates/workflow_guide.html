What this page is

A step-by-step walkthrough of how bank statements turn into the CA's GST working sheet and ready-to-upload GSTR-1 JSON return in this app - so you (or the CA) can follow it without asking anyone. This mirrors the CA's own written workflow specification (NUTAN INCOME WORKFLOW) exactly.

1

Upload branch statements Income & Output GST

Drag and drop PDF/Excel branch statements (or a whole folder). Nothing changes here from how you've always done it - the app reads each account's income as credit total minus debit total for the period, rounds to 2 decimals, and auto-computes CGST/SGST at 9% each.

2

Check the "Needs Review" banner Income & Output GST

After upload, a yellow banner appears if anything needs a second look - a GL/PL code the app has never seen before, a manual-entry code (see step 3), or a locker/guarantee code with signs of an internal transfer. Click "Show these entries" to jump straight to them.

3

Classify GL/PL codes (once per code) Manage GL/PL Codes

This is the one-time setup step. Open Manage GL/PL Codes (button above the branch table) and tell the app how to treat specific codes - see the reference table below for exactly which ones. Type a code or particulars into the search box to find it fast; the field also suggests matches as you type.

  • New/unrecognized codes default to 18% Taxable until classified - never silently exempt.
  • Editing a code here retroactively fixes every already-uploaded entry using it.
4

Fix manual-entry and ledger-balance figures Income table / Ledger section

Codes marked Manual (like PL 3230, PL 3320) show a pencil icon next to their amount in the main table - click it to type the correct figure. GL 1878/1879/1880 and exempt-income codes appear lower on the page under "GST Payable Ledger & Exempt Income", each with its own pencil icon if the closing balance needs correcting.

5

Export the CA Working Sheet Income & Output GST

Click Export CA Working Sheet (Excel). Every branch tab, Sheet1, and SUMMARY SHEET GST are filled from real uploaded data, plus two verification tabs:

  • GST Payable Reconciliation - each branch's computed CGST/SGST/IGST vs. the bank's own ledger figure, with the difference. Any branch tab where the difference exceeds ₹10 turns red automatically.
  • Exempt Income Working Sheet - this month vs. last month's closing balance for each classified exempt-income code, and the difference.
6

Upload B2B registered client invoices (optional) Income & Output GST

If the bank issued taxable service invoices to corporate customers or companies with a GSTIN, click "Upload B2B Invoices" in the B2B Outward Registered Supplies bar. Upload an Excel (.xlsx) or CSV invoice file. The system automatically reads customer GSTIN, invoice number, date, and tax amounts, and maps them to Table 4 (B2B) in GSTR-1.

  • The app automatically nets these B2B supplies out of Table 7 (B2CS retail) on matching intra/inter-state sides so revenue is never double-reported.
  • If the bank has no corporate registered clients for the month, skip this step — all retail banking income flows directly to Table 7.
7

Generate & Download official GSTR-1 JSON Income & Output GST

Click the green "Download GSTR-1 JSON" button next to the CA Working Sheet button. A verification dialog opens displaying a live summary of all GSTR-1 sections:

  • Bank GSTIN & Period: Pre-filled with bank GSTIN and standard filing period code (e.g., 072026 for July 2026).
  • Table 4 (B2B): Invoice count and taxable value for registered corporate clients.
  • Table 7 (B2CS): Retail banking supplies (net intra-state and inter-state banking revenue).
  • Table 8 (Nil/Exempt): Interest on loans/advances and other statutory exempt banking turnover.
  • Table 12 (HSN/SAC): Mandatory SAC code 9971 (Financial & Related Services) covering 100% of the bank's gross turnover at 18% GST.

Click "Confirm & Download JSON" to save the official GSTR1_<GSTIN>_<FP>.json file (conforming to GST Portal Offline Schema v3.1+).

8

Upload JSON directly to GST Portal GST Portal (gst.gov.in)

Submit your GSTR-1 return in under two minutes without manual typing:

  • Log in to gst.gov.in → Go to Services > Returns > Returns Dashboard.
  • Select the Financial Year and Month → Click Search.
  • Under Details of outward supplies of goods or services (GSTR-1), click PREPARE OFFLINE.
  • Go to the Upload tab, click Choose File, and select your downloaded .json file.
  • The GST Portal validates and imports all tables (B2B, B2CS, Nil, HSN) automatically with zero errors. Proceed to generate summary and file.

Common questions

How does the system ensure B2B invoices aren't double-counted in Table 7 (B2CS)?

The app automatically nets uploaded B2B supplies against total CBS branch income on the matching intra/inter-state sides. Table 7 only receives net retail banking transactions, preventing any duplicate taxation.

Can I preview the JSON summary before downloading?

Yes! Clicking "Download GSTR-1 JSON" opens a modal summary displaying the exact tax figures and turnover for Table 4, Table 7, Table 8, and Table 12 before downloading the .json file.

What if the bank GSTIN changes or we need to file for another state?

You can edit the 15-character GSTIN directly in the GSTR-1 popup dialog before confirming download. The JSON envelope and filing period code update automatically.

Why does a code default to 18% Taxable instead of asking me first?

Because guessing "exempt" on income that's actually taxable is the dangerous direction to be wrong in for GST. The app defaults to the safe-but-flagged option and waits for you to confirm via Manage GL/PL Codes - it never silently exempts something.

A branch tab turned red in the export. What does that mean?

The GST the app computed from that branch's income differs from what the bank's own GL 1878/1879/1880 ledger says by more than ₹10. Check the GST Payable Reconciliation sheet for the exact numbers, then verify against the branch's original statement.

The Exempt Income sheet shows "—" for last month. Is that a bug?

No - it means there's no captured closing balance for the previous period yet (either it's the first month this code has been tracked, or the statement for that period wasn't uploaded). It will fill in automatically from the next month onward.

I deleted a code by mistake, or classified something wrong. What happens to already-uploaded data?

Nothing is deleted from your records. Editing or deleting a code re-flags every entry using it as "Needs Review" (or recomputes it, if you're correcting rather than removing) so you can catch and fix it before filing - it never silently changes numbers you can't see.
